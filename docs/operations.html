실행과 복구

시작 스크립트는 모델 서버와 작업 서버를 감시합니다. 비정상 종료되면 지연 후 다시 실행하며, 디스크에 저장한 작업 상태를 읽습니다.

일시 중지와 취소의 차이

  • 일시 중지: 현재 역할 이후 새 단계를 시작하지 않습니다. 작업 큐는 보존합니다.
  • 취소: 해당 작업의 다음 단계와 완료 처리를 막습니다. 이미 진행 중인 모델 호출이나 파일 쓰기는 즉시 중단되지 않을 수 있습니다.
  • 종료: PowerShell에서 .\Stop.ps1을 실행합니다. 현재 역할에 최대 250초를 주고 상태를 보존한 뒤 종료합니다.

다시 이어가기

새 작업은 자동 복구가 기본입니다. 중단되면 현재 역할부터 재개합니다. 반복 충돌은 제한 후 중단으로 남깁니다. 자동 복구를 껐거나 실패로 남은 작업은 기록을 확인하고 ‘다시 이어가기’를 선택하세요.

파일 저장이 반복될 수 있어 원자적 교체를 사용합니다. 향후 엔진 명령·게시 같은 외부 효과가 있는 도구를 붙일 때는 별도의 중복 방지 규칙이 필요합니다.

장시간 실행

실행 가능한 작업이 있으면 큐를 계속 처리하고, 모두 끝나면 대기합니다. 에이전트가 임의로 업무 범위를 늘리지는 않습니다.

24시간 실측은 아직 하지 않았습니다.

단기 연속 실행과 실제 프로세스 종료·복구를 확인했습니다. PC가 절전·종료되거나 로그아웃하면 계속 실행된다고 보장하지 않습니다. Windows 자동 시작과 절전 설정은 자동으로 바꾸지 않습니다.

새 설정과 기존 작업

팀 구성을 바꾸어도 기존 작업은 원래 배정을 유지합니다. Slack 설정은 저장 후 연결을 다시 구성합니다. 연결을 끄면 로컬 작업은 계속 진행할 수 있습니다.

설정을 바꾸는 동안

팀 설정은 저장하지 않은 변경 사항을 표시합니다. 되돌리기를 누르면 마지막으로 저장한 팀 구성을 다시 불러옵니다. 설정 탭 사이를 이동해도 입력은 유지됩니다. 저장 전 창을 닫거나 새로 고치면 브라우저가 변경 확인을 요청할 수 있습니다. Slack 토큰은 브라우저 저장소에 보관하지 않으며 성공적으로 저장한 뒤 입력칸에서 지웁니다.

서버가 잠시 끊겼을 때

처음 연결에 실패하면 3초 뒤 자동으로 다시 연결합니다. 연결된 뒤에는 2.5초 간격으로 상태를 확인합니다. 일반 요청은 30초, 문서 요청은 15초 후 시간 초과로 처리합니다. 저장 요청이 시간 초과되었다면 실제 저장 여부를 확인한 뒤 다시 시도하세요.

여러 창에서 설정할 때

다른 창에서 먼저 저장하면 현재 화면의 이전 버전으로 덮어쓰지 않고 충돌을 안내합니다. 입력은 유지됩니다. 최신 버전 확인 후 현재 입력을 검토해 저장하거나, 저장된 설정으로 되돌리기를 선택하세요. 팀과 Slack 설정에 적용됩니다.

수동 재시도의 수정 한도

실패 작업은 필요한 계획 또는 개발 단계부터 다시 시작하고 중단 작업은 현재 단계부터 이어갑니다. 통신 실패 횟수와 재시도 대기 시간을 초기화하며, 처음 정한 자동 수정 한도를 새로 제공합니다. 수정 회차는 누적합니다. 이전 보고서·ZIP은 작업 폴더의 attempts/r회차에 보관합니다.

중단된 VM 입력 단계

키·텍스트·클릭 단계 중 종료되면 이미 입력되었는지 확정할 수 없어 자동 복구를 보류합니다. 게스트 상태를 확인한 뒤 수동으로 재개하세요. 수동 재개는 입력을 다시 전달할 수 있습니다. 실행 계획·단계를 읽지 못해도 자동 재실행하지 않습니다. 일반 파일 작업은 저장된 현재 단계에서 재실행하며 체크포인트 폴더를 자동으로 되돌리는 방식은 아닙니다.
