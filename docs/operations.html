실행과 복구

작업은 한 번에 하나씩 실행됩니다.

  1. 잠시 멈추려면 상단 일시 중지를 누르세요.
  2. 다시 진행하려면 계속 실행을 누르세요.
  3. 실패한 작업은 기록을 확인한 뒤 다시 이어가세요.
종료·재시작·복구 안내

시작 스크립트는 모델 서버와 작업 서버를 감시합니다. 비정상 종료되면 지연 후 다시 실행하며, 디스크에 저장한 작업 상태를 읽습니다.

일시 중지와 취소의 차이

  • 일시 중지: 현재 역할 이후 새 단계를 시작하지 않습니다. 작업 큐는 보존합니다.
  • 취소: 해당 작업의 다음 단계와 완료 처리를 막습니다. 이미 진행 중인 모델 호출이나 파일 쓰기는 즉시 중단되지 않을 수 있습니다.
  • 종료: PowerShell에서 .\Stop.ps1을 실행합니다. 현재 역할에 최대 250초를 주고 상태를 보존한 뒤 종료합니다.

다시 이어가기

새 작업은 자동 복구가 기본입니다. 중단되면 현재 역할부터 재개합니다. 반복 충돌은 제한 후 중단으로 남깁니다. 자동 복구를 껐거나 실패로 남은 작업은 기록을 확인하고 ‘다시 이어가기’를 선택하세요.

파일 저장이 반복될 수 있어 원자적 교체를 사용합니다. 향후 엔진 명령·게시 같은 외부 효과가 있는 도구를 붙일 때는 별도의 중복 방지 규칙이 필요합니다.

장시간 실행

실행 가능한 작업이 있으면 큐를 계속 처리하고, 모두 끝나면 대기합니다. 에이전트가 임의로 업무 범위를 늘리지는 않습니다.

24시간 실측은 아직 하지 않았습니다.

단기 연속 실행과 실제 프로세스 종료·복구를 확인했습니다. PC가 절전·종료되거나 로그아웃하면 계속 실행된다고 보장하지 않습니다. Windows 자동 시작과 절전 설정은 자동으로 바꾸지 않습니다.

새 설정과 기존 작업

팀 구성을 바꾸어도 기존 작업은 원래 배정을 유지합니다. Slack 설정은 저장 후 연결을 다시 구성합니다. 연결을 끄면 로컬 작업은 계속 진행할 수 있습니다.

설정을 바꾸는 동안

팀 설정은 저장하지 않은 변경 사항을 표시합니다. 되돌리기를 누르면 마지막으로 저장한 팀 구성을 다시 불러옵니다. 설정 탭 사이를 이동해도 입력은 유지됩니다. 저장 전 창을 닫거나 새로 고치면 브라우저가 변경 확인을 요청할 수 있습니다. Slack 토큰은 브라우저 저장소에 보관하지 않으며 성공적으로 저장한 뒤 입력칸에서 지웁니다.

서버가 잠시 끊겼을 때

처음 연결에 실패하면 3초 뒤 자동으로 다시 연결합니다. 연결된 뒤에는 2.5초 간격으로 상태를 확인합니다. 일반 요청은 30초, 문서 요청은 15초 후 시간 초과로 처리합니다. 저장 요청이 시간 초과되었다면 실제 저장 여부를 확인한 뒤 다시 시도하세요.

여러 창에서 설정할 때

다른 창에서 먼저 저장하면 현재 화면의 이전 버전으로 덮어쓰지 않고 충돌을 안내합니다. 입력은 유지됩니다. 최신 버전 확인 후 현재 입력을 검토해 저장하거나, 저장된 설정으로 되돌리기를 선택하세요. 팀과 Slack 설정에 적용됩니다.

수동 재시도의 수정 한도

실패 작업은 필요한 계획 또는 개발 단계부터 다시 시작하고 중단 작업은 현재 단계부터 이어갑니다. 통신 실패 횟수와 재시도 대기 시간을 초기화하며, 처음 정한 자동 수정 한도를 새로 제공합니다. 수정 회차는 누적합니다. 이전 보고서·ZIP은 작업 폴더의 attempts/r회차에 보관합니다.

중단된 VM 입력 단계

키·텍스트·클릭 단계 중 종료되면 이미 입력되었는지 확정할 수 없어 자동 복구를 보류합니다. 게스트 상태를 확인한 뒤 수동으로 재개하세요. 수동 재개는 입력을 다시 전달할 수 있습니다. 실행 계획·단계를 읽지 못해도 자동 재실행하지 않습니다. 일반 파일 작업은 저장된 현재 단계에서 재실행하며 체크포인트 폴더를 자동으로 되돌리는 방식은 아닙니다.

운영 관측과 장시간 데모 시험

팀 설정 → 작업 환경 → 설치 상태 확인에서 서버 응답·작업 스레드·대기/진행 수를 확인할 수 있습니다. 스레드 생존과 감독 기록 신선도는 실제 작업 진행이나 모델 준비 상태를 보장하지 않습니다. 모델·VM·Slack에 접속하지 않는 조회입니다. heartbeat 파일 저장이 일시적으로 실패해도 작업 루프는 계속 처리합니다.

고급 검증은 python soak.py --hours 24로 시작합니다. 프로젝트 소스를 별도 runtime/soak 폴더에 고정하고 데모 큐·HTTP·결과물 해시만 관측합니다. 실제 모델 주소는 비활성 포트로 바꾸고 운영 데이터·모델·VM·Slack을 복사하지 않습니다. 기본 30초 관측·5분마다 데모 작업 한 개이며 컴퓨터가 깨어 있어야 합니다.

시험 작업은 기본 60초 안에 끝나야 하며 큐가 일시 중지되면 시험을 실패로 기록합니다. 검증을 마친 결과물은 최근 10개만 남기고 대화·작업 DB는 보존합니다. 새 격리 실행 폴더만 정리하며 운영 데이터는 대상이 아닙니다. 전체 폴더가 256MiB를 넘으면 다음 용량 확인 때 중단하고 증거를 남깁니다(5초 간격 감시이며 강제 디스크 할당량은 아닙니다). 필요하면 --task-timeout, --keep-artifacts, --max-mib로 조절하세요. 기존 실행에는 다음 시험부터 적용됩니다.

각 실행 폴더의 status.json에서 경과 시간·샘플·검증 작업·연결 실패·자식 재시작을 확인하세요. 실행 폴더에 stop 파일을 만들거나 포그라운드 실행에서 Ctrl+C를 누르면 소유한 분리 앱만 종료합니다. 상태 파일만으로 생존을 단정하지 말고 해당 PID·실행 폴더도 확인하세요. 짧은 시험은 demo_24h_observed가 false이며, 24시간 관측이 끝나도 실제 모델·엔진 업무 24시간 검증을 뜻하지 않습니다.

감독 코드는 종료한 자식의 로그 핸들을 정리하고 시작 실패를 기록해 재시도합니다. 안정 운용 60초 후 연속 실패 지연을 초기화합니다. 이미 실행 중인 구버전 감독 프로세스에는 다음 정상 Start.ps1 실행부터 적용됩니다. 파일 해시와 체크포인트 복사는 큰 파일도 통째로 메모리에 읽지 않습니다.

복원 후 Slack 대기 항목 검토

복원한 데이터의 대기 알림·수신 지시는 별도 보류 상태로 시작합니다. Slack을 다시 연결하기 전후에 Slack 설정에서 항목별 내용을 확인하고 선택 재개·제외하세요. 전체 과거 기록을 자동 재전송하지 않으며 선택하지 않은 항목은 보류합니다. 제외는 기록 삭제가 아닙니다.

단계 인계 중 앱이 종료된 경우

일반 단계의 인계·알림 대기열과 다음 단계 이동을 함께 저장합니다. 검증 실패로 자동 수정할 때도 수정 요청과 회차 변경을 함께 저장합니다. 저장 중 종료되면 일부 인계만 남기지 않고 원래 단계에서 복구합니다. SQL 저장 오류는 기록을 확인한 뒤 재개하세요.

이 보장은 단계 기록에 적용됩니다. 이미 실행한 파일 쓰기·VM 입력을 되돌리지는 않습니다. VM 입력 단계는 기존처럼 자동 복구를 보류합니다. 최종 결과는 별도의 발행 확인 절차를 거칩니다. 여러 파일 교체 자체를 하나의 파일시스템 연산으로 만드는 방식은 아닙니다.

보고서 발행 확인

새 보고서는 최종 인계·상태·파일 해시 확인을 함께 저장한 뒤 제공합니다. 작성 중 종료되거나 상태 저장이 실패하면 미완성 보고서와 완료 알림을 제공하지 않습니다. 수정 한도를 소진한 경우의 요청·실패 상태·실패 보고서도 함께 저장합니다.

앱에서 파일을 열 때 커밋된 발행 정보와 크기·SHA-256을 대조합니다. 파일이 없거나 발행 확인 전이거나 내용이 바뀐 파일은 목록에서 제외됩니다. 기록을 확인하고 재개한 뒤 결과를 다시 조회하세요. 수동 재개 시 이전 보고서는 이력 폴더에 보존하고, 새 회차의 발행 확인 전까지 현재 다운로드에서는 제외합니다. 디스크의 파일 자체가 여러 개 동시에 교체되는 것은 아니므로 미완성 파일을 폴더에서 직접 볼 수는 있습니다. 발행 정보가 없는 구형 보고서는 기존 방식으로 제공합니다. VM 화면 기록은 이 보고서 발행 확인과 별도입니다.

포트 충돌과 이 프로젝트의 종료

일반 시작은 8765·8766 포트를 먼저 확인하고 다른 앱을 자동 재사용하지 않습니다. 포트를 열 수 없으면 기존 앱을 해당 프로젝트에서 종료하거나 직접 실행의 다른 포트를 선택하세요. 포트 확인과 실제 시작 사이에 다른 앱이 들어올 수 있어 충돌 검사는 실행 성공 보장이 아닙니다.

앱은 포트를 확보한 뒤 작업 복구·Slack 수신을 시작합니다. 종료는 .\Stop.ps1이며 데모는 .\Stop.ps1 -Port 8767입니다. 스크립트와 감독은 프로젝트·실행 인스턴스의 파일에 종료를 요청하고 고정 포트에 종료 HTTP를 보내지 않습니다. 실행 기록이 없으면 다른 앱을 추측해 종료하지 않습니다. 종료 요청 저장은 종료 완료 확인과 다르며 진행 중인 단계의 정리를 기다려 주세요.

runtime/app-포트.json은 모델·VM 설치 파일이 아닌 실행 기록입니다. 남은 기록만으로 프로세스가 살아 있다고 판단하지 않습니다. 예전 코드로 이미 실행 중인 감독에는 변경이 즉시 반영되지 않으므로 정상 종료 후 다시 시작해야 합니다.

백업 파일을 확인할 수 없을 때

백업 ZIP과 상태 기록은 독립된 일반 파일이어야 합니다. 연결된 파일이나 지나치게 큰 상태 기록은 완료로 표시하지 않습니다. 다른 프로그램이 파일을 사용 중이면 닫은 뒤 같은 요청을 다시 확인하세요. 원본 파일은 자동으로 삭제하거나 고치지 않습니다.

백업 완료 표시와 복원 가능 여부는 다릅니다. 복원 전 검사를 실행해 내용을 확인하세요.

백업 재시도 후 상태 확인

같은 요청을 다시 처리할 때 이전 도우미의 실패·대기 기록이 현재 상태를 덮지 않도록 구분합니다. 백업 목록과 요청 상태를 새로 확인하세요. 기존 백업과 기록은 삭제하지 않습니다.

서버 변경 적용 상태

설치 진단의 서버 변경 적용에서 시작 때의 소스·설정과 현재 파일을 비교합니다. ‘재시작 필요’라면 진행 중인 작업을 마친 뒤 앱을 정상 종료하고 시작하세요. 화면 새로고침만으로는 서버 코드가 적용되지 않습니다.

파일을 읽을 수 없거나 설정이 손상되면 ‘확인 필요’로 표시합니다. 파일과 권한을 확인한 뒤 다시 진단하세요. 이 표시는 실제 작업 성공이나 모델·VM 연결 검증이 아닙니다.
