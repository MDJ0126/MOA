# 화면 비조작 고도화 기준

> 아래 완료 결과는 당시 범위의 검증 기록입니다. 최신 소스·운영 앱 반영·전체 지속 목표의 완료를 뜻하지 않습니다. 현재 작업과 검증 범위는 [CONTINUOUS_GOAL.md](CONTINUOUS_GOAL.md)를 확인하세요.

2026-10-23. VM 시작·종료·키 입력·마우스·화면 캡처 및 컴퓨터 유즈를 실행하지 않습니다. 임시 데이터의 단위·HTTP·jsdom 검증으로 아래 10개 항목을 확인하며, 통과한 항목 수 / 10을 이번 작업의 진행률로 보고합니다.

1. 여러 창의 팀 설정 저장 충돌 감지와 최신 값 보존
2. Slack 설정·암호문 동시 커밋, 실패 시 전체 롤백, 기존 암호화 파일 호환과 명시적 복구
3. 동일 요청 ID의 동시 등록 및 응답 유실 후 재전송 중복 방지
4. 취소된 단계의 늦은 응답이 다음 담당자·외부 발송 큐로 전달되지 않음
5. 수동 재시도 시 대기·실패 횟수 초기화, 수정 예산 갱신, 이전 보고서 보존
6. 다른 담당자 메시지가 많아도 본인에게 보낸 최근 지시를 모델 컨텍스트에 유지
7. 전체·담당자별 대화 JSON 내보내기
8. 비정상 UTF-8·큰 페이지/커서 값과 비정상 설정 입력 처리
9. 입력을 보존하는 설정 충돌 안내와 작업 재전송·내보내기 DOM 흐름
10. 사용자 문서, 전체 비화면 회귀 검증과 실행 중 작업이 없는 상태에서 앱 반영

검증 명령은 `python -m unittest -q`, `python verify_system.py`, `python verify_ui.py`, `python verify_refinement.py`입니다. VM 관련 단위 테스트는 제어 메서드나 연결을 대체하거나 자원 잠금·설정 데이터만 검사하며 실제 게스트를 조작하지 않습니다. `verify_vm_live.py`, `verify_live_smoke.py --vm` 등 실제 VM 실행 검증은 이번 범위에서 실행하지 않습니다.

설정 버전 검사는 현재 UI가 보내는 `expected_updated` 값으로 수행합니다. 이를 보내지 않는 기존 스크립트는 이전 API 호환성을 유지합니다. 중복 등록 방지는 같은 `request_key` 재전송에 적용되며, 브라우저 화면을 새로 열거나 서로 다른 요청 ID를 사용한 작업을 내용만 보고 자동 병합하지 않습니다.

수동 재시도는 기존 회차의 보고서·ZIP을 `data/tasks/<ID>/attempts/r<회차>/`에 보관합니다. 수정 회차는 누적하고 새로 허용하는 자동 수정 수는 처음 지정한 한도대로 갱신합니다. 중단 작업은 현재 단계부터, 실패 작업은 필요한 계획 또는 개발 단계부터 재개합니다. 이미 진행 중인 모델 호출·파일 쓰기를 즉시 강제 중단하는 기능은 아닙니다.

Slack 토큰은 DPAPI 암호문을 설정과 같은 SQLite 트랜잭션에 저장합니다. 기존 `slack.secrets`는 읽기 호환과 백업을 위해 보존하며, 새 암호문이 저장된 이후에는 데이터베이스 값을 우선합니다. API 응답·대화 내보내기에 암호문이나 토큰을 포함하지 않습니다. 작업 내용 자체에 사용자가 적은 민감 정보는 내보내기에 포함될 수 있습니다.

최종 결과: 10/10 기준 통과. 단위 테스트 45개, HTTP·DOM·대량 기록 검증을 통과했습니다. 실행 중이거나 대기 중인 작업이 없는 상태에서 앱 프로세스만 재시작했고, 대화 내보내기 v1 응답·UI 파일 해시·사용자 문서로 반영을 확인했습니다. 이번 작업 중 실제 VM 입력·캡처·시작·종료 테스트는 수행하지 않았으며 운영 데이터에 새 VM 화면 파일도 생성되지 않았습니다. 상세 결과는 `data/non-screen-progress.json`에 있습니다.
