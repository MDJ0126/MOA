데이터와 저장 위치

작업 기록과 설정은 이 PC에 저장합니다.

  1. 작업 환경의 설치 상태와 데이터 관리를 여세요.
  2. 백업과 복원 준비에서 백업을 만드세요. 앱 종료 후 진행됩니다.
  3. ZIP에는 작업 내용·암호화 토큰이 포함됩니다. 개인 보관하세요.
저장 위치·복원·공유 범위

모델 추론과 작업 기록은 이 PC에서 처리합니다. Slack을 연결하면 지시·진행 상황·보고 내용은 Slack 서비스를 거칩니다.

토큰 보호

설정 화면은 저장된 토큰을 다시 보여주지 않습니다. 입력란을 비워 두면 기존 토큰을 유지합니다. 변경할 때만 새 토큰을 입력하세요. ‘연결 끄기’는 전송과 수신을 중지하고 토큰은 보존합니다.

결과물 ZIP은 작업 파일·보고서와 사용한 경우 VM 화면 기록을 포함합니다. 시스템의 Slack 토큰 저장소와 모델 서버 인증 키 파일은 자동으로 포함하지 않습니다.

로컬 주소

화면과 모델 서버는 loopback 주소에서만 수신합니다. 같은 네트워크의 다른 기기나 휴대폰에서 이 PC의 localhost 주소로 직접 접속할 수는 없습니다. Slack 메시지는 사용할 수 있지만 파일 다운로드를 위한 외부 공개는 구성하지 않았습니다.

파일 도구와 코드 실행

파일 도구는 작업 폴더 밖 경로와 하드링크 파일 읽기를 차단합니다. 큰 폴더의 목록은 일부만 반환하고 생략 여부를 표시합니다. 하지만 Python 테스트는 현재 사용자 권한으로 실행되며 OS 보안 샌드박스가 아닙니다. 역할별 기록 분리는 별도 Windows 계정이나 VM 격리를 뜻하지 않습니다.

백업과 이동

앱을 정상 종료한 뒤 필요한 data 기록과 결과물을 백업하세요. 토큰은 다른 사용자·PC에서 복원할 수 없을 수 있으므로 다시 입력하는 편이 적절합니다. 모델 파일은 공식 출처에서 다시 받을 수 있습니다.

VM 화면 기록

공유 VM 작업은 단계 전후 화면을 작업 폴더에 PNG로 저장하고 결과 ZIP에 포함합니다. 게스트 화면의 작업 내용과 입력된 정보가 보일 수 있으므로 보고서·ZIP을 공유하기 전에 화면 파일도 검토하세요. VM 화면에는 호스트 PC 화면을 캡처하지 않습니다.

검증 가능한 백업과 새 폴더 복원

Python을 MOA_PYTHON으로 지정했다면 아래 PowerShell 명령의 python을 & $env:MOA_PYTHON으로 바꾸세요.

앱과 감시 관리자를 정상 종료한 뒤 PowerShell에서 python data_backup.py backup data backups/workspace.zip을 실행하세요. 실행 중인 앱의 잠금이 있으면 백업하지 않습니다. 기존 ZIP을 덮어쓰지 않으므로 매번 새 파일명을 사용하세요. 백업은 작업 기록·결과물·설정과 암호화된 토큰을 포함하므로 개인 보관하세요. 모델 인증 키·관리자 상태·VM 실행 상태는 제외합니다. 모델·런타임·VM 디스크·ISO는 별도 보관 또는 재설치 대상입니다.

python data_backup.py restore backups/workspace.zip restored-data는 파일 크기·SHA-256·SQLite 무결성을 검사하고 아직 존재하지 않는 새 폴더에만 복원합니다. 기존 data를 덮어쓰지 않습니다. 복원본은 작업이 일시 중지되고 Slack·VM 연결이 꺼진 상태입니다. 이전 VM 사용권은 원문 이력으로 보관하며 새 실행에 적용하지 않습니다. Slack·VM 설정의 원문도 보관하며, 손상된 선택 설정은 연결이 꺼진 기본 구성으로 복구합니다. 토큰 암호문은 그대로 유지하므로 연결 정보를 확인한 뒤 다시 켜세요. 앱을 종료한 상태에서 기존 data를 다른 이름으로 보존한 뒤 복원본을 data로 옮겨 사용하세요. 다른 Windows 계정·PC에서는 Slack 토큰을 다시 입력하고 연결·작업 목록을 검토한 뒤 재개하세요.

저장한 실행 환경이 손상됐으면 원문을 보관하고 기본 설정으로 복구합니다. 복원만으로 VM·원격 장비에 연결하지 않습니다.

복원 전 백업 요청과 도우미 PID는 별도 이력으로 보관하며 새 PC의 실행 중인 작업으로 취급하지 않습니다. 복원 후 필요한 백업은 새로 요청하세요. 기존 ZIP은 덮어쓰지 않습니다.

Slack 토큰 저장과 복구

새 토큰은 Windows 사용자 DPAPI 암호문으로 데이터베이스에 저장하며 설정과 함께 한 번에 커밋합니다. 기존 slack.secrets 파일은 읽기 호환과 백업을 위해 보존합니다. 다른 Windows 계정에서 토큰을 읽지 못해도 설정 화면을 열 수 있습니다. 복구 안내의 새 토큰으로 교체를 선택하고 필요한 모든 토큰을 입력한 뒤 저장하면 새 계정의 암호문으로 교체합니다. 연결 확인만으로 설정을 바꾸지는 않습니다.

설정 화면에서 백업하기

팀 설정 → 작업 환경 → 백업과 복원 준비에서 ‘앱 종료하고 백업 만들기’를 누르세요. 미저장 설정은 먼저 저장하거나 되돌려 주세요. 현재 역할을 정리해 앱을 종료하고, 별도 백업 프로세스가 앱·감시 관리자 잠금 해제를 기다린 뒤 backups 폴더에 새 ZIP을 저장합니다. VM을 종료하거나 조작하지 않습니다. 종료 대기는 최대 5분이며 실패하면 같은 이름의 status.json에 안내를 남깁니다. ZIP을 기존 파일 위에 덮어쓰지 않습니다.

백업이 완료된 뒤 Start.ps1로 다시 실행하고 ‘백업 목록 새로 확인’을 누르면 최근 백업 상태를 볼 수 있습니다. ‘복원 전 검사’는 압축 해제 크기 512 MB까지 임시 폴더에서 전체 파일과 데이터베이스를 검사하고 작업·대화 수를 알려줍니다. 현재 데이터를 교체하지 않습니다. 더 큰 백업은 CLI 복원으로 새 폴더에서 검사하세요. SHA-256은 파일 변경 탐지이며 백업 작성자의 신원을 인증하는 전자서명은 아닙니다.

백업 응답이 끊긴 경우

백업 요청 ID는 이 브라우저의 로컬 저장소와 앱 데이터베이스에 남습니다. 응답이 끊겼다고 미접수로 단정하거나 새 요청을 만들지 않습니다. 같은 화면에서 다시 누르면 같은 ID로 확인·재전송하며 앱을 재실행한 뒤에는 접수 상태를 조회합니다. 이미 완료한 요청은 기존 백업을 표시하고 앱을 다시 종료하지 않습니다. 로컬 저장소를 차단하거나 지운 경우 자동 조회가 제한되므로 백업 목록의 최근 상태도 확인하세요. 앱을 너무 일찍 재실행하면 기존 백업이 앱 잠금 해제를 기다릴 수 있습니다. 같은 요청으로 백업 버튼을 다시 누르면 앱을 종료하고 기존 백업을 이어갑니다.

백업 ZIP은 있지만 완료 상태를 확인할 수 없으면 기존 파일을 보존하고 복원 전 검사를 안내합니다. 파일 존재만으로 완료나 무결성을 보장하지 않습니다. 안내를 확인한 뒤 다시 백업 버튼을 누르면 새 요청 ID로 별도 백업을 만듭니다. 중복 도우미는 작업별 잠금으로 동시에 백업하지 못하게 합니다.

큰 백업과 데이터베이스 일관성

데이터 파일은 64KB씩 읽고 기록해 파일 하나 전체를 메모리에 올리지 않습니다. 데이터베이스는 SQLite 스냅샷으로 저장하며 WAL에 커밋된 내용도 포함합니다. WAL·공유 메모리 파일 자체는 묶음에 넣지 않습니다. 앱을 정상 종료해야 한다는 조건은 그대로 적용됩니다.

하드링크와 대소문자가 충돌하는 복원 경로는 거절합니다. Windows에서 파일명 대소문자를 바꾸더라도 모델 인증 키와 VM 실행 상태는 백업에서 제외됩니다. 복원 크기 제한과 새 폴더 조건은 동일합니다. 백업은 모델·VM 디스크의 복제본이 아닙니다.

복원 폴더의 일시적인 사용 중 오류

Windows에서 검증한 복원 폴더를 최종 이름으로 바꿀 때 파일 잠금 관련 오류가 나면 짧게 최대 4번 시도합니다. 추가 대기는 합계 약 0.5초까지이며 권한이나 잠금이 계속되면 오류를 그대로 반환합니다. 기존 복원 대상은 덮어쓰지 않으며 재시도 도중 대상이 생겨도 중단합니다. 오류가 지속되면 해당 폴더를 사용하는 프로그램을 확인하고 새 대상 폴더로 다시 복원하세요. 앱이 잠금 프로세스를 강제로 종료하거나 권한을 변경하지는 않습니다.

VM 자동 설치 파일 준비

VM 파일 준비가 완료되고 ISO의 무인 설치 지원이 확인되면 설치 파일 준비를 펼치세요. VM 전용 계정과 새 비밀번호를 정하고 Windows 판본을 선택합니다. 생성한 비밀번호는 게스트 로그인용으로 별도 보관하세요. 준비 버튼은 꺼진 소유 VM에 설치 파일을 연결하며 VM을 부팅하지 않습니다. 완료 표시는 OS 설치 완료가 아닙니다.

비밀번호는 일반 설정이나 명령 인자에 저장하지 않습니다. 임시 비밀번호 입력 파일은 명령 종료 후 삭제하며 실패 시 보호 폴더에 남았음을 기록합니다. 자동 설치 응답 파일에도 비밀번호가 포함될 수 있어 runtime/vbox-private의 전용 보호 폴더에 보관합니다. Windows는 현재 사용자와 SYSTEM만 허용하는 상속 차단 권한을 확인하며, 다른 OS는 0700 권한을 확인합니다. 관리자 접근까지 차단하거나 메모리에서 비밀번호를 지우는 기능은 아닙니다.

보호 폴더는 일반 데이터 백업에서 제외됩니다. VM 이전은 별도로 준비해야 합니다. 설치가 중단되면 상태를 확인하고 자동 재실행하지 마세요. 준비 기록 정리는 보호 폴더나 VM 파일을 삭제하지 않습니다. 실제 VirtualBox 설치·부팅은 아직 미검증입니다.

복원한 VM 준비 기록

데이터를 복원하면 VirtualBox 검토 계획·VM 준비·설치 준비 기록은 활성 설정에서 분리해 보관합니다. 준비 기록 확인에 보관 건수를 표시하며 원래 VM에 자동 연결하지 않습니다. 같은 PC·프로젝트에 복원해도 동일합니다. 새 준비 내용을 확인하면 현재 설치·등록·파일 충돌을 다시 검사합니다. 기존 VM이나 보호 설치 파일은 삭제하지 않습니다.

기록은 복원 데이터베이스의 vbox_restore_archive에 원문으로 보존하며 다음 백업에도 포함합니다. 바이너리 기록은 원본 바이트를 복구할 수 있는 16진수로 보관합니다. 이 보관은 VM 디스크·ISO·보호 응답 파일의 복원이 아닙니다. VM 이전과 실제 OS 설치·실행 연결은 별도 확인해야 합니다.
