WHEN SOMETHING STOPS

문제 해결

화면에 접속할 수 없어요

Start.ps1이 실행 중인지 확인하세요. 주소는 http://127.0.0.1:8765입니다. 다른 앱이 같은 포트를 쓰고 있거나 관리자가 중복 실행되면 시작 로그를 확인해야 합니다.

Slack 토큰을 넣었는데 연결되지 않아요

  • xoxb-는 Bot User OAuth Token, xapp-는 App-Level Token입니다.
  • App-Level Token에 connections:write가 있는지 확인합니다.
  • Socket Mode와 app_mention·message.im 이벤트를 켭니다.
  • 앱을 워크스페이스에 설치하고 채널에 봇을 초대합니다.
  • 지시를 보낸 멤버의 ID가 허용 목록에 있는지 확인합니다.

Slack 오류 코드

표시확인할 내용
invalid_auth / token_revoked토큰을 다시 발급받아 입력합니다.
missing_scope필요한 권한을 추가하고 앱을 다시 설치합니다.
not_in_channel / channel_not_found채널 ID와 봇 초대 여부를 확인합니다.
rate_limited전송을 재시도할 때까지 기다립니다. 개발 작업은 다시 실행하지 않습니다.

작업이 ‘확인 필요’로 남아요

작업을 열고 실행 근거를 확인하세요. 필수 파일 누락, Python 테스트 실패, 모델 응답 형식 오류, 통신 오류를 구분해 기록합니다. 요구사항을 더 작은 단위로 나누거나 고정 테스트를 추가해 재시도할 수 있습니다.

메모리 사용량이 높아요

모델 추론이 끝난 후 30초 동안 새 요청이 없으면 메모리를 해제합니다. 진행 중인 큰 작업은 일시 중지하고 다른 무거운 프로그램을 정리하세요. 프리셋 변경은 모델 자체의 크기를 줄이지는 않습니다.

다른 PC에서 Slack 토큰을 읽지 못해요

토큰은 저장한 Windows 사용자 계정에 묶여 있습니다. 다른 PC나 사용자로 옮겼다면 Slack 연결 정보에 토큰을 다시 입력하세요. 비밀 파일을 Git이나 공유 ZIP에 넣지 마세요.

로그 위치

앱 폴더의 data/app.stderr.log, data/model.stderr.log, data/supervisor.stderr.log를 확인할 수 있습니다. 외부에 공유하기 전에 작업 내용과 개인정보를 검토하세요.

가이드를 불러오지 못했어요

앱 서버가 실행 중인지 확인한 뒤 문서 영역의 다시 불러오기를 누르세요. 작업 기록과 설정은 문서 요청 실패로 지워지지 않습니다.

Python 실행 파일을 지정하고 싶어요

PowerShell에서 $env:MOA_PYTHON = 'C:\Python313\python.exe'처럼 실제 설치한 실행 파일의 전체 경로를 지정한 뒤 Install.ps1 또는 Start.ps1을 실행하세요. 해당 PowerShell 세션에 적용됩니다. 지정 경로를 사용할 수 없거나 Python 3.11 미만, sqlite3·ssl을 읽을 수 없는 경우 설치와 시작을 중단하고 안내합니다. 다른 Python으로 자동 변경하지 않습니다. 지정값을 지우려면 Remove-Item Env:MOA_PYTHON을 실행하세요.

모델 통신 오류와 다시 시도

작업 상세의 오류 안내에서 입력 길이·인증·모델 경로·연결 실패·응답 형식을 구분합니다. HTTP 오류 원문을 그대로 보고서에 복사하지 않고 상태 번호와 오류 범주를 기록합니다. 400·401·403·404·413·422와 인증서·주소·응답 형식 문제는 같은 요청을 자동으로 반복하지 않습니다. 입력·서버 설정을 확인하고 작업을 나누거나 수동으로 재개하세요.

연결 단절·시간 초과와 408·425·429·500·502·503·504는 작업의 장애 횟수 한도 안에서 자동으로 최대 2회 재시도합니다. 기본 간격은 5초·10초이며 서버의 Retry-After가 더 길면 최대 5분까지 반영합니다. 다른 작업이나 일시 중지 때문에 실제 실행은 더 늦어질 수 있습니다. 화면에는 실행 가능 시점과 일시 중지 상태를 안내합니다. 한도를 넘으면 실패로 보존하고 서버 상태 확인 후 수동 재개를 안내합니다.

키·텍스트·클릭을 지정한 VM 단계는 입력이 전달됐을 수 있어 자동 재시도하지 않습니다. 게스트 상태를 확인한 뒤 수동으로 재개하세요. 수동 재개는 해당 단계의 입력을 다시 전달할 수 있습니다. 이 보호는 게스트 화면이 목표대로 바뀌었다는 판정이 아닙니다.
