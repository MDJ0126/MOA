QUICK GUIDE

문제 해결

먼저 상태를 확인하고 해당 문제만 해결하세요.

  1. 작업 환경의 설치 상태와 데이터 관리를 여세요.
  2. 설치 상태 확인을 누르세요.
  3. 확인 필요 항목과 작업 오류를 읽고 다시 시도하세요.
문제별 해결 방법

화면에 접속할 수 없어요

Start.ps1이 실행 중인지 확인하세요. 주소는 http://127.0.0.1:8765입니다. 다른 앱이 같은 포트를 쓰고 있거나 관리자가 중복 실행되면 시작 로그를 확인해야 합니다.

Slack 토큰을 넣었는데 연결되지 않아요

  • xoxb-는 Bot User OAuth Token, xapp-는 App-Level Token입니다.
  • App-Level Token에 connections:write가 있는지 확인합니다.
  • Socket Mode와 app_mention·message.im 이벤트를 켭니다.
  • 앱을 워크스페이스에 설치하고 채널에 봇을 초대합니다.
  • 지시를 보낸 멤버의 ID가 허용 목록에 있는지 확인합니다.

Slack 오류 코드

표시확인할 내용
invalid_auth / token_revoked토큰을 다시 발급받아 입력합니다.
missing_scope필요한 권한을 추가하고 앱을 다시 설치합니다.
not_in_channel / channel_not_found채널 ID와 봇 초대 여부를 확인합니다.
rate_limited전송을 재시도할 때까지 기다립니다. 개발 작업은 다시 실행하지 않습니다.

작업이 ‘확인 필요’로 남아요

작업을 열고 실행 근거를 확인하세요. 필수 파일 누락, Python 테스트 실패, 모델 응답 형식 오류, 통신 오류를 구분해 기록합니다. 요구사항을 더 작은 단위로 나누거나 고정 테스트를 추가해 재시도할 수 있습니다.

메모리 사용량이 높아요

기본 설정은 모델 추론이 끝난 후 300초 동안 새 요청이 없으면 메모리를 해제합니다. 응답 지연을 줄이기 위해 그동안 모델을 메모리에 유지합니다. 진행 중인 큰 작업은 일시 중지하고 다른 무거운 프로그램을 정리하세요. 프리셋 변경은 모델 자체의 크기를 줄이지는 않습니다.

다른 PC에서 Slack 토큰을 읽지 못해요

토큰은 저장한 Windows 사용자 계정에 묶여 있습니다. 다른 PC나 사용자로 옮겼다면 Slack 연결 정보에 토큰을 다시 입력하세요. 비밀 파일을 Git이나 공유 ZIP에 넣지 마세요.

로그 위치

앱 폴더의 data/app.stderr.log, data/model.stderr.log, data/supervisor.stderr.log를 확인할 수 있습니다. 외부에 공유하기 전에 작업 내용과 개인정보를 검토하세요.

초기 연결을 자동 재시도해도 이미 표시된 설정의 미저장 입력은 유지합니다. 저장 여부를 확인한 뒤 계속 편집하세요. 저장된 값으로 바꾸려면 설정의 되돌리기를 선택하세요. 페이지를 닫은 뒤 입력을 복구하는 기능은 아닙니다.

가이드를 불러오지 못했어요

앱 서버가 실행 중인지 확인한 뒤 문서 영역의 다시 불러오기를 누르세요. 작업 기록과 설정은 문서 요청 실패로 지워지지 않습니다.

모델 다운로드가 중간에 멈췄어요

같은 설치 명령을 다시 실행하면 .part 파일에서 이어받습니다. 최종 SHA-256 검증이 실패하면 잘못된 부분 파일을 지우므로 다시 실행하세요. 정식 모델 파일은 검증 성공 전까지 교체하지 않습니다. 다른 설치가 진행 중이라는 안내가 나오면 먼저 실행한 설치를 확인하세요. 사용 중인 DLL 교체 오류라면 앱과 감시 관리자를 정상 종료한 뒤 설치를 다시 실행하세요.

PowerShell 스크립트가 차단돼요

정책을 바꾸지 않고 앱 폴더에서 Python으로 준비·실행할 수 있습니다. 아래 명령은 순서대로 실행하며 오류가 나면 다음 단계로 넘어가지 마세요. 모델이 준비돼 있으면 두 번째 명령은 생략하세요.

python -m pip install --target runtime/pythonlibs -r requirements.txt
python src/install_model.py
python src/supervisor.py

종료는 같은 폴더의 다른 터미널에서 python src/stop_app.py입니다. 모델 없이 체험하려면 python src/app.py --demo, 종료는 python src/stop_app.py --port 8767을 사용하세요.

Start.ps1은 앱·감독 프로세스의 종료 코드를 전달합니다. 시작 실패가 성공으로 처리되지 않도록 자동 실행 도구에서도 0이 아닌 코드를 확인하세요.

Python 실행 파일을 지정하고 싶어요

PowerShell에서 $env:MOA_PYTHON = 'C:\Python313\python.exe'처럼 실제 설치한 실행 파일의 전체 경로를 지정한 뒤 Install.ps1 또는 Start.ps1을 실행하세요. 해당 PowerShell 세션에 적용됩니다. 지정 경로를 사용할 수 없거나 Python 3.11 미만, sqlite3·ssl을 읽을 수 없는 경우 설치와 시작을 중단하고 안내합니다. 다른 Python으로 자동 변경하지 않습니다. 지정값을 지우려면 Remove-Item Env:MOA_PYTHON을 실행하세요.

모델 통신 오류와 다시 시도

작업 상세의 오류 안내에서 입력 길이·인증·모델 경로·연결 실패·응답 형식을 구분합니다. HTTP 오류 원문을 그대로 보고서에 복사하지 않고 상태 번호와 오류 범주를 기록합니다. 400·401·403·404·413·422와 인증서·주소·응답 형식 문제는 같은 요청을 자동으로 반복하지 않습니다. 입력·서버 설정을 확인하고 작업을 나누거나 수동으로 재개하세요.

연결 단절·시간 초과와 408·425·429·500·502·503·504는 작업의 장애 횟수 한도 안에서 자동으로 최대 2회 재시도합니다. 기본 간격은 5초·10초이며 서버의 Retry-After가 더 길면 최대 5분까지 반영합니다. 다른 작업이나 일시 중지 때문에 실제 실행은 더 늦어질 수 있습니다. 화면에는 실행 가능 시점과 일시 중지 상태를 안내합니다. 한도를 넘으면 실패로 보존하고 서버 상태 확인 후 수동 재개를 안내합니다.

키·텍스트·클릭을 지정한 VM 단계는 입력이 전달됐을 수 있어 자동 재시도하지 않습니다. 게스트 상태를 확인한 뒤 수동으로 재개하세요. 수동 재개는 해당 단계의 입력을 다시 전달할 수 있습니다. 이 보호는 게스트 화면이 목표대로 바뀌었다는 판정이 아닙니다.

단계 인계 중 앱이 종료된 경우

일반 단계의 인계·알림 대기열과 다음 단계 이동을 함께 저장합니다. 검증 실패로 자동 수정할 때도 수정 요청과 회차 변경을 함께 저장합니다. 저장 중 종료되면 일부 인계만 남기지 않고 원래 단계에서 복구합니다. SQL 저장 오류는 기록을 확인한 뒤 재개하세요.

이 보장은 단계 기록에 적용됩니다. 이미 실행한 파일 쓰기·VM 입력을 되돌리지는 않습니다. VM 입력 단계는 기존처럼 자동 복구를 보류합니다. 최종 결과는 별도의 발행 확인 절차를 거칩니다. 여러 파일 교체 자체를 하나의 파일시스템 연산으로 만드는 방식은 아닙니다.

보고서 발행 확인

새 보고서는 최종 인계·상태·파일 해시 확인을 함께 저장한 뒤 제공합니다. 작성 중 종료되거나 상태 저장이 실패하면 미완성 보고서와 완료 알림을 제공하지 않습니다. 수정 한도를 소진한 경우의 요청·실패 상태·실패 보고서도 함께 저장합니다.

앱에서 파일을 열 때 커밋된 발행 정보와 크기·SHA-256을 대조합니다. 파일이 없거나 발행 확인 전이거나 내용이 바뀐 파일은 목록에서 제외됩니다. 기록을 확인하고 재개한 뒤 결과를 다시 조회하세요. 수동 재개 시 이전 보고서는 이력 폴더에 보존하고, 새 회차의 발행 확인 전까지 현재 다운로드에서는 제외합니다. 디스크의 파일 자체가 여러 개 동시에 교체되는 것은 아니므로 미완성 파일을 폴더에서 직접 볼 수는 있습니다. 발행 정보가 없는 구형 보고서는 기존 방식으로 제공합니다. VM 화면 기록은 이 보고서 발행 확인과 별도입니다.

추가 지시 단계·확인 표시 오류

저장된 담당 단계가 잘못됐거나 수동 확인 표시를 해석할 수 없으면 작업을 보류합니다. 단계와 확인 값을 임의로 초기화해 재실행하지 않습니다. 다른 정상 작업은 계속 처리할 수 있습니다.

이 경우 반복해서 재개하거나 새 지시로 덮어쓰지 말고 원래 요청·대화와 정상 백업을 확인하세요. 추가 지시 정보가 바이너리로 손상된 경우 목록에는 형식 오류를 표시하고 원본 값은 DB에 보존합니다. 정상 백업을 새 데이터 폴더에 복원하거나 필요한 내용을 새 작업으로 맡겨 주세요. 값이 정상인 수동 확인 보류는 기존처럼 상태 확인 후 다시 이어가기로 재개할 수 있습니다. 이미 실행된 파일 쓰기·VM 입력은 되돌리지 않습니다.
