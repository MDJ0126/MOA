공유 VM 작업 환경

VM 한 대를 팀원이 차례로 사용합니다.

  1. 설치 안내에 따라 VM을 준비하세요.
  2. 공유 VM 사용을 켜고 환경을 저장하세요.
  3. VM을 시작한 뒤 화면 확인과 수동 조작에서 화면을 확인하세요.
설치·동작 설정·제한

팀원마다 컴퓨터를 만들지 않고, VM 한 대를 여러 에이전트가 차례로 사용합니다. 사용자 PC의 마우스·키보드를 조작하지 않고 VM 내부에만 입력합니다. 로컬 파일 작업은 VM 없이 그대로 사용할 수 있습니다.

PC별 실행 환경 추천

개발 대상은 Windows·Linux·macOS, 실행 위치는 현재 PC·공유 VM·원격 PC/Mac 중 선택합니다. 자원 점유 목표는 25·50·75%입니다. 현재 여유 RAM과 논리 CPU 수·측정된 CPU 여유로 VM 시작 구성을 추천하며 메모리가 부족하거나 측정하지 못하면 추천을 보류합니다. 이 비율은 강제 자원 제한이 아니며 Windows/Linux의 CPU 점유율은 연속 조회 사이의 평균이며 첫 조회는 미확인입니다. GPU 점유율은 측정하지 않습니다. 원격 장비에는 로컬 PC의 사양을 적용하지 않습니다.

선호 환경 저장은 설치·연결을 실행하지 않습니다. 새 작업의 작업 환경에서 저장한 실행 환경을 선택하면 현재 PC와 대상 OS를 확인해 실행합니다. 현재 PC를 선택하고 OS가 일치하는 경우를 지원하며, 미연결 VM·원격 환경이나 다른 OS는 접수하지 않습니다. 기존 로컬 파일·공유 VM 선택은 각각 기존 경로를 사용합니다. VirtualBox 작업 실행·원격 실행·Mac 연결은 아직 미구현이며 macOS는 Mac 장비 연결을 기준으로 준비합니다. macOS 호스트의 총 RAM은 조회하지만 현재 여유 RAM·CPU 점유율은 미확인으로 표시합니다. 새 추천은 현재 점유율로 다시 추천을 눌러 확인하며 실행 중인 VM 자원을 자동 변경하지 않습니다.

작업에 저장 환경 적용

선호 환경을 저장한 뒤 새 작업의 실행 설정과 완료 조건에서 작업 환경을 저장한 실행 환경으로 선택합니다. 접수 시 대상 OS·실행 위치·아키텍처를 고정하고 모델에도 전달합니다. 설정이 다른 창에서 바뀌면 최신 설정 확인을 요청합니다. 이미 접수한 작업은 이후 선호 환경 변경으로 실행 대상을 바꾸지 않습니다. 다른 OS나 아키텍처의 PC에서 복원하면 실행 전에 보류합니다. 보고서의 실행 대상과 Python 검사 범위를 확인하세요. 데모는 대상 정보가 있어도 실제 실행 테스트를 하지 않습니다.

VirtualBox VM 파일 준비

실행 위치를 공유 VM으로 선택하고 VirtualBox 준비를 펼칩니다. 프로젝트 내부의 Windows·Linux x64 ISO를 지정한 뒤 준비 내용을 확인하세요. 현재 사양의 추천 프리셋 또는 가볍게·균형·개발 구성을 검토합니다. 자동 추천의 자원값도 계획에 고정하며 파일 준비 중 다시 배분하지 않습니다. 공식 체크섬 대조를 펼치면 배포처에서 확인한 SHA-256을 선택 입력할 수 있습니다. 입력하지 않아도 파일 내용 지문은 계산하지만 공식 값 미대조로 표시합니다. 배포처 진위 자체를 자동 확인하는 기능은 아닙니다. Windows 11은 CPU 최소 2개·RAM 최소 4GB를 기준으로 하며, 개발 도구 성능을 보장하는 값은 아닙니다.

기본 설치 위치의 VirtualBox 7.2 도구(다른 위치는 MOA_VBOXMANAGE 환경 변수에 실제 VBoxManage 절대 경로 지정), 등록 이름/UUID 충돌, 기존 저장 폴더, 디스크 여유를 확인합니다. VM 파일 준비를 누르면 프로젝트의 runtime/vbox에 전용 VM 정의·VDI를 만들고 VirtualBox에 등록한 뒤 ISO를 연결합니다. Windows 디스크는 128GB, Linux는 64GB이며 해당 용량과 호스트 여유 4GB의 디스크 공간을 확인합니다. 네트워크·클립보드·드래그 앤 드롭은 끕니다. 부팅·OS 설치·화면 조작은 수행하지 않으며 기존 QEMU 환경을 교체하지 않습니다. ISO SHA-256 내용 지문과 감지 OS를 검토 계획에 고정하고 파일 준비 직전에 다시 대조합니다. Windows 11 x64 또는 인식한 주요 Linux x64 계열과 다른 ISO는 준비하지 않습니다. 부팅 호환성, Windows 사용권과 CPU 지원 여부는 별도 확인해야 합니다.

중간 오류와 완료 응답 유실은 준비 기록 확인으로 검토합니다. 큰 ISO는 내용 지문 계산에 시간이 걸릴 수 있습니다. 준비 확인 응답이 늦거나 유실돼도 완료된 검토 계획은 같은 입력에서 준비 기록 확인으로 다시 표시할 수 있습니다. OS 감지의 무인 설치 지원 표시는 VirtualBox 감지값이며 모아가 OS를 설치했다는 뜻이 아닙니다. preparing 기록만으로 프로세스가 살아 있다고 판정하지 않습니다. 중단 기록이나 기존 파일을 자동 삭제·재실행하지 않습니다. 앱 종료 중 중단됐다면 VirtualBox 관리자와 runtime/vbox의 해당 이름을 확인해 수동으로 복구하세요. 중단된 준비 복구를 열고 정리 가능한지 확인하세요. 현재 사용자의 VirtualBox 등록 목록과 해당 전용 폴더가 모두 없을 때만 준비 기록만 정리할 수 있습니다. 준비·복구는 runtime/vbox-setup.lock의 프로젝트 공용 잠금으로 조정하므로 다른 데이터 폴더의 앱도 동시에 진행하지 않습니다. 새 VM 이름에는 runtime 소유 표식을 포함합니다. 데이터 기록이 없어도 프로젝트의 등록 이름이나 runtime/vbox의 파일이 남아 있으면 새 준비를 차단합니다. 외부에서 VM 이름과 폴더를 바꾼 경우에는 등록 상태를 직접 확인하세요. 등록이나 폴더가 남으면 VirtualBox에서 해당 VM을 직접 검토하세요. 조회 실패·낯선 등록 목록·파일 권한 오류는 없다고 가정하지 않습니다. 자동 VM 삭제·생성 취소/복구·OS 무인 설치·시작/종료·작업 연결은 미구현입니다. 백업은 준비 메타데이터를 포함하지만 runtime/vbox의 실제 VM 디스크는 포함하지 않습니다. runtime/vbox-owner.id는 준비 runtime의 소유 표식이며 백업에 포함하지 않습니다. 소유 표식이 없거나 다른 복원본·이전 버전 기록은 자동 연결하거나 정리하지 않습니다. 표식을 임의로 새로 만들어 기존 기록에 붙이지 마세요. 기록 정리와 감사 이력은 함께 저장하며, 실패하면 둘 다 유지합니다. 같은 정리 요청의 재전송은 이전 결과를 돌려주고 새 준비 기록을 지우지 않습니다.

이 준비 경로는 x64 호스트의 Windows·Linux VM용입니다. macOS·ARM은 Mac/해당 아키텍처 실행 환경 연결을 사용하세요. VirtualBox 자체 도구 설치와 시스템 드라이버 변경은 자동 수행하지 않습니다. Oracle 7.2 명령 안내 · Windows 11 요구 사항

처음 설치

프로젝트 폴더의 PowerShell에서 아래 명령을 실행합니다. Python 3.11 이상이 필요하며, 시스템 드라이버와 레지스트리를 변경하지 않고 프로젝트 안에 QEMU와 경량 데스크톱을 준비합니다.

.\Install.ps1 -WithVM

QEMU 배포 파일의 SHA-512, 압축 도구의 GitHub 배포 SHA-256, Tiny Core의 공개 체크섬을 대조합니다. Xorg 데스크톱 패키지를 포함한 ISO와 구성 내역은 runtime/vm-downloads에 보존합니다.

설정하고 시작하기

  1. 팀 설정 → 작업 환경에서 공유 VM 사용을 켭니다.
  2. 기본 RAM 512MB·CPU 1개로 시작합니다. 이 값은 게스트 RAM이며 QEMU 자체의 추가 메모리 사용량은 별도입니다. 부팅 ISO에는 준비한 runtime/vm-downloads/moa-desktop.iso를 지정합니다.
  3. 환경을 저장한 뒤 VM 시작을 누릅니다. 화면 확인으로 게스트 부팅 완료를 확인합니다. 부팅 메뉴에서 Enter가 필요할 수 있습니다.
  4. 새 작업의 실행 설정과 완료 조건에서 공유 VM 화면 사용을 선택합니다.

기본 가속 방식은 TCG이며 빠른 하드웨어 가상화를 보장하지 않습니다. 첫 부팅은 그래픽 모듈을 불러오는 동안 시간이 걸릴 수 있습니다. WHPX는 Windows 기능과 실제 지원 상태를 확인한 뒤 선택해야 합니다. 기본 VM 인터넷 연결은 꺼져 있습니다.

한 번에 한 팀원

각 단계의 담당자가 OS 파일 잠금을 얻고 사용자를 기록합니다. 다른 작업이나 수동 입력은 동시에 화면을 사용하지 못합니다. 단계가 끝나거나 오류가 발생하면 잠금을 해제합니다. 작업 도중 VM을 사용할 수 없으면 VM 작업은 실패 또는 대기 상태로 남기며 호스트 화면으로 대신 실행하지 않습니다.

화면 동작 지정

현재 모델은 비전 모델이 아닙니다. 화면을 보고 알아서 메뉴를 찾는 기능은 아직 없습니다. 단계별 입력 동작을 JSON으로 명시하고, 실제 실행 기록과 전후 화면으로 결과를 확인합니다.

[
  {"role":"developer","action":"key","keys":["ret"]},
  {"role":"developer","action":"wait","seconds":1},
  {"role":"reviewer","action":"capture"}
]

지원 동작은 key, text, click, wait, capture입니다. text는 영문·숫자·기호 160자 이내이고 Enter는 줄바꿈으로 보낼 수 있습니다. 키는 ret, esc, tab, ctrl, alt, f1~f12 등을 사용합니다. click의 x·y는 화면의 좌상단 0부터 우하단 32767까지 정규화한 좌표입니다. 한 작업에 최대 40개 동작을 지정할 수 있습니다. 재시도 시 같은 단계의 입력이 다시 실행될 수 있으므로 결제·게시 같은 중복 외부 효과가 있는 업무를 자동화하지 마세요.

VM 화면을 사용한다고 호스트에서 실행하는 Python 테스트까지 격리되는 것은 아닙니다. 게스트와 호스트 사이의 파일 자동 동기화도 아직 없습니다.

기록과 종료

작업 상세의 에이전트별 VM 화면 기록에서 단계 전후 화면을 열 수 있습니다. 화면 파일은 작업 보고서와 ZIP에도 포함합니다. VM 전원 끄기는 게스트 전원을 끄므로 게스트 앱에서 먼저 저장하세요. 앱 재시작과 VM 전원은 별개이며, 실행 중인 VM에 다시 연결합니다.

Windows 작업용으로 확장

기본 Linux는 화면 제어 검증용 라이브 환경이며 재부팅 시 게스트 변경을 보존하지 않습니다. Windows 앱은 별도 설치 매체·라이선스와 설치된 qcow2/img 디스크가 필요합니다. 프로젝트 내부 디스크를 지정하면 디스크를 우선 부팅합니다. Windows·Unreal 실행과 GPU 가속은 아직 검증하지 않았습니다. 현재 약 16GB RAM 환경에서는 여러 VM 대신 한 대를 공유하는 구성을 유지하세요.

다른 창에서 설정을 바꾼 경우

이전 버전을 연 창에서 저장하면 충돌을 알리고 현재 입력을 유지합니다. ‘입력 유지하고 최신 버전 확인’으로 저장 버전을 확인한 뒤 입력을 검토하고 다시 저장하세요. 저장된 내용으로 돌아가려면 ‘저장된 설정으로 되돌리기’를 누르세요. VM이 실행 중이거나 다른 팀원이 사용 중이면 설정을 저장할 수 없습니다.

작업은 접수 시점의 환경 값을 보관합니다. 실제 RAM·CPU·ISO·디스크·가속·네트워크·사용 여부가 달라지면 해당 작업은 새 환경에서 자동 실행하지 않습니다. 같은 값을 다시 저장해 저장 시각만 바뀐 경우에는 기존 작업을 유지합니다.

작업 취소와 사용권

에이전트는 VM 사용권을 확보한 뒤 체크포인트와 검증을 진행합니다. 사용권이 없으면 검증 코드·VM 입력을 반복하지 않고 대기하며, 작업과 대화에 VM 사용권 대기로 표시합니다. 이 대기는 모델 실패 횟수를 사용하지 않습니다. 진입 후 오류를 진입 전 대기로 간주해 입력을 자동 반복하지 않습니다.

VM 단계 진입 전과 입력 사이에 취소·종료 상태를 확인합니다. 취소를 확인하면 남은 입력과 마지막 화면 캡처를 진행하지 않고 사용권을 반납합니다. 이미 전달한 입력을 되돌리거나 진행 중인 한 동작을 즉시 중단하는 기능은 아닙니다. 사용권 기록 저장 중 오류가 나도 잠금을 정리하고 다음 담당자가 다시 사용할 수 있게 합니다.

필요한 설정만 열기

기본 화면에는 공유 VM 사용 여부·상태·저장·전원 동작을 표시합니다. 메모리·CPU·부팅 이미지·디스크·가속·네트워크는 성능과 부팅 설정에서 바꿉니다. 화면 확인과 수동 조작, 설치 상태와 데이터 관리는 각각 펼쳐서 사용하세요. 접는 동작은 설정을 저장하거나 되돌리지 않습니다.

JSON 없이 화면 동작 정하기

작업을 맡길 때 실행 설정과 완료 조건에서 공유 VM 환경을 선택하고 VM 화면 동작을 여세요. 동작 추가를 누른 뒤 담당 단계와 키 입력·텍스트 입력·클릭·대기·화면 기록 중 하나를 선택합니다. 같은 단계의 동작은 화살표로 순서를 바꾸거나 제거할 수 있습니다. 팀의 단계 순서는 유지되며 같은 단계 안에서 지정한 순서로 실행합니다.

클릭 위치는 화면 왼쪽·위쪽을 0%, 오른쪽·아래쪽을 100%로 입력합니다. 텍스트는 영문·숫자·기호 160자까지, 대기는 동작당 0~5초, 전체 동작은 40개까지입니다. 고급 JSON 편집도 유지하며 형식이 깨졌을 때 원문을 지우거나 자동 수정하지 않습니다. 선택 편집 화면은 입력을 구성할 뿐 VM을 즉시 조작하지 않습니다. 작업을 접수하고 해당 단계가 실행될 때 동작을 전달합니다. 현재 모델은 화면의 의미를 이해하거나 목표 달성을 자동 판정하지 않습니다.

WHPX 가속을 선택한 경우

새 VM을 시작하기 전에 Windows Hypervisor Platform의 공식 조회 API로 하이퍼바이저 상태를 확인합니다. 사용할 수 없거나 확인하지 못하면 VM 프로세스를 만들지 않습니다. TCG로 바꾸거나 호스트 설정을 확인하세요. 앱이 Windows 기능을 자동 변경하지는 않습니다. Home 여부로 WHPX를 단정하지 않으며, 조회 성공은 실제 QEMU 가속 부팅 성공을 보장하지 않습니다. 이미 실행 중인 VM의 상태 확인은 유지합니다.

Microsoft WHvGetCapability 설명

VM 자동 설치 파일 준비

VM 파일 준비가 완료되고 ISO의 무인 설치 지원이 확인되면 설치 파일 준비를 펼치세요. VM 전용 계정과 새 비밀번호를 정하고 Windows 판본을 선택합니다. 생성한 비밀번호는 게스트 로그인용으로 별도 보관하세요. 준비 버튼은 꺼진 소유 VM에 설치 파일을 연결하며 VM을 부팅하지 않습니다. 완료 표시는 OS 설치 완료가 아닙니다.

비밀번호는 일반 설정이나 명령 인자에 저장하지 않습니다. 임시 비밀번호 입력 파일은 명령 종료 후 삭제하며 실패 시 보호 폴더에 남았음을 기록합니다. 자동 설치 응답 파일에도 비밀번호가 포함될 수 있어 runtime/vbox-private의 전용 보호 폴더에 보관합니다. Windows는 현재 사용자와 SYSTEM만 허용하는 상속 차단 권한을 확인하며, 다른 OS는 0700 권한을 확인합니다. 관리자 접근까지 차단하거나 메모리에서 비밀번호를 지우는 기능은 아닙니다.

보호 폴더는 일반 데이터 백업에서 제외됩니다. VM 이전은 별도로 준비해야 합니다. 설치가 중단되면 상태를 확인하고 자동 재실행하지 마세요. 준비 기록 정리는 보호 폴더나 VM 파일을 삭제하지 않습니다. 실제 VirtualBox 설치·부팅은 아직 미검증입니다.

설치 대상 변경과 입력 보존

설치 대상을 바꿔도 계정·판본·비밀번호 초안은 유지합니다. 이전 입력을 다른 VM에 적용하지 않도록 준비 버튼을 잠급니다. 입력 지우기를 누른 뒤 현재 VM용으로 다시 설정하세요. 이전 요청의 늦은 응답은 현재 대상 화면을 덮어쓰지 않습니다. 준비 기록 확인으로 실제 기록을 검토하세요.

복원한 VM 준비 기록

데이터를 복원하면 VirtualBox 검토 계획·VM 준비·설치 준비 기록은 활성 설정에서 분리해 보관합니다. 준비 기록 확인에 보관 건수를 표시하며 원래 VM에 자동 연결하지 않습니다. 같은 PC·프로젝트에 복원해도 동일합니다. 새 준비 내용을 확인하면 현재 설치·등록·파일 충돌을 다시 검사합니다. 기존 VM이나 보호 설치 파일은 삭제하지 않습니다.

기록은 복원 데이터베이스의 vbox_restore_archive에 원문으로 보존하며 다음 백업에도 포함합니다. 이 보관은 VM 디스크·ISO·보호 응답 파일의 복원이 아닙니다. VM 이전과 실제 OS 설치·실행 연결은 별도 확인해야 합니다.

실행 상태를 확인할 수 없을 때

QEMU VM 기록이 손상되거나 시작 확인이 끝나지 않으면 중지된 것으로 간주하지 않고 추가 기동을 보류합니다. 실행 중인 VM의 설정이 다르거나 설정 기록이 없을 때도 자동 재사용하지 않습니다.

종료가 확인되기 전에는 실행 기록을 보존합니다. 연결이 끊긴 경우 실제 프로세스와 data/vm/qemu.log를 확인하세요. 종료 여부를 모르는 상태에서 기록을 지워 새 VM을 시작하지 마세요.

자동 추천이 없을 때

현재 준비 경로의 지원 여부와 CPU·여유 RAM을 확인한 경우에만 자동 선택합니다. CPU 측정이 처음이거나 정보가 없으면 잠시 후 현재 점유율로 다시 추천을 눌러 확인하세요.

지원하지 않는 환경이나 예산 부족을 임의의 기본 프리셋으로 대체하지 않습니다. 수동 프리셋은 파일 준비용 선택이며 실제 부팅·연결 완료를 뜻하지 않습니다.
